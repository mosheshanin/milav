# Анализ проекта и план улучшений

Дата анализа: 13.10.2026. Основа: код репозитория, тесты, сборка, сквозная проверка в Chromium.
Лимиты Cloudflare и Google в этом документе приведены по состоянию на момент анализа; перед решением проверять актуальные (правило из `CLAUDE.md`).

## Где мы сейчас

- Монорепозиторий: `apps/web` (React, Vite, Tailwind), `apps/api` (Cloudflare Worker, Hono, D1), `packages/shared` (правила продукта), `content` (уроки в JSON), `tools` (генерация озвучки, стенд распознавания, сквозной тест).
- Около 5 000 строк кода, 29 коммитов, 87 юнит-тестов и сквозной тест урока и викторины в Chromium (`tools/e2e-lesson.mjs`).
- Работает: вход через Telegram (подпись `initData`), один урок на 10 слов, четыре этапа, викторина на 25 вопросов, очки, статусы, прогресс в D1, автодеплой Cloudflare.
- Размер: основной JS 281 КБ (около 86 КБ gzip), шаблоны букв 182 КБ грузятся только на этапе письма.
- Ожидает владельца: токен бота (добавлен, вход в Telegram подтверждён), ключ Google TTS для озвучки, решение по источнику картинок.

## Что сделано хорошо

- Правила продукта лежат в одном месте (`packages/shared/src/constants.ts`), очки и статус не хранятся, а выводятся из данных.
- Сервер сам решает, что засчитывать: этап «говори» отмечается только по проверке речи, урок открывается к викторине только после 10 пройденных слов, доступ к уроку проверяется на сервере.
- Дизайн-токены в одном месте, тесты на контент и на правила, сквозной тест в браузере.
- Решения владельца и открытые вопросы записаны в `CLAUDE.md`, новые чаты не теряют контекст.

## 15 улучшений

Приоритет: **до запуска** (без этого опасно выпускать), **после запуска** (первые недели), **позже**. Усилие: S (до дня), M (несколько дней), L (неделя и больше).

### Безопасность и честность результатов

**1. Проверять этапы «пиши» и «печатай» на сервере.** До запуска, S–M.
Сейчас `POST /api/progress/stage` принимает этапы listen, write и type без доказательств: один запрос curl засчитывает этап, а три из четырёх этапов слова клиентские. Очки, статус и будущая таблица лидеров накручиваются без труда. Решение: для «печатай» клиент шлёт набранное слово, сервер сверяет с `word.he`; для «пиши» клиент шлёт штрихи, сервер прогоняет их тем же распознавателем (код чистый TypeScript, его нужно вынести из `apps/web` в `packages/shared`). «Слушай» можно оставить как есть, но слово считать выученным только при подтверждённых остальных.

**2. Викторина, которую выдаёт и проверяет сервер.** До запуска таблицы лидеров, M.
`POST /api/quiz/submit` принимает от клиента число правильных ответов, то есть любой может «сдать» урок и поднять статус. Решение: `quiz/start` выдаёт вопросы и подписанный токен, ответы проверяются по одному на сервере (выбор по id слова, речь через Whisper, письмо через распознаватель), результат считается на сервере. Побочная польза: статистика по вопросам покажет слова, которые путают, и плохую озвучку.

**3. Лимиты на дорогие вызовы и заголовки безопасности.** До запуска, S.
`/api/speech/check` вызывает Whisper, бесплатная квота Workers AI ограничена в день, а лимитов на пользователя нет: один человек (или скрипт) исчерпает её для всех. Решение: лимит запросов на пользователя в минуту и в сутки (таблица в D1 или встроенный rate limiting Cloudflare), чтение тела запроса с ограничением размера, понятное сообщение «попробуйте позже». Заодно добавить `_headers` с CSP, `X-Content-Type-Options`, `Referrer-Policy` и `frame-ancestors` для Telegram.

**4. Платежи Stars и приватность по правилам Telegram.** До запуска подписки, M.
Нужны: обработка `pre_checkout_query` и `successful_payment` на Worker с проверкой подписи вебхука, идемпотентность (повторная доставка не должна дать доступ дважды или не выдать вовсе), таблица покупок со сроком, команда поддержки платежей и возвраты, политика конфиденциальности, удаление данных пользователя по запросу (имя, username, прогресс), отдельный экран «О приложении» с авторами картинок (см. `CREDITS.md`).

### Архитектура и масштабирование

**5. Контент: манифест и ленивая загрузка уроков, доступ по API.** До первых платных уроков, M.
`content/index.ts` импортирует все уроки статически, они попадают и в клиент, и в Worker. При 500 уроках это тысячи слов в основном бандле, а платные уроки будут видны любому, кто откроет файл (защита на сервере тогда бессмысленна). Решение: лёгкий манифест (темы, уроки, id) в бандле, слова урока отдаются API с проверкой доступа и кэшируются на клиенте; JSON-схема и валидатор вместо одной только тестовой проверки.

**6. Агрегаты и счётчики в базе.** После запуска, S–M.
Главный экран запрашивает прогресс отдельным запросом на каждый бесплатный урок (при сотнях уроков это сотни запросов), а `getTotals` на каждый ответ делает два `COUNT(*)` по таблицам. Решение: один запрос `/api/home` со сводкой, поля `points` и `passed_lessons` в `users` с обновлением в той же транзакции, индекс `word_progress(user_id, completed_at)`. Это же основа для таблицы лидеров. Бесплатный лимит D1 (запись и чтение строк в сутки) станет узким местом при росте, счётчики снимают основную часть чтений.

**7. Медиа (озвучка, картинки) вынести в R2 или CDN.** После запуска, M.
Сейчас файлы лежат рядом с приложением. На 5 000 слов это десятки мегабайт в git, а у статики Workers есть лимит на число файлов (на бесплатном тарифе порядка 20 000, проверить): слова, фразы-примеры и картинки подойдут к нему быстро. Решение: бакет R2, пути вида `/media/<версия>/<id>.mp3`, долгий кэш, загрузка из GitHub Actions; в JSON остаётся только относительный путь.

**8. CI и безопасные выкладки.** До запуска, S.
Cloudflare собирает только фронтенд (`npm run build`): типы API и тесты при деплое не запускаются, а коммиты идут прямо в `main`, то есть сломанная версия сразу уходит пользователям. Миграции D1 при деплое не применяются, значит возможен код без нужной таблицы. Решение: GitHub Actions (типы, тесты, сборка, сквозной тест в Chromium), команда сборки в Cloudflare `typecheck && test && build`, шаг `wrangler d1 migrations apply` до `wrangler deploy`, второе окружение (staging) с отдельной базой, правило «откат — это revert коммита».

**9. Наблюдаемость.** После запуска, S.
Сейчас об ошибках никто не узнает. Решение: включить Workers Logs (`observability` в `wrangler.jsonc`), эндпоинт приёма ошибок клиента, простые события воронки (открыл урок, прошёл слово, начал и сдал викторину, сбой микрофона), `/api/health` с проверкой базы, уведомление при расходе 80% бесплатных квот (D1, Workers AI). Без этого нельзя понять, где люди бросают.

### Юзабилити и продукт

**10. Навигация и возобновление.** До запуска, S.
Экран хранится только в памяти: перезагрузка или свёрнутое приложение ведут на главную, системная кнопка «назад» закрывает приложение. Решение: Telegram BackButton, простая маршрутизация (хеш в адресе), кнопка «Продолжить со слова 4, этап «пиши»», сохранение места в базе.

**11. Повторение и удержание.** После запуска, M–L.
Сейчас слово выучено навсегда после одного прохождения, забывание не учитывается: главная причина ухода из языковых приложений. Решение: интервальные повторения (раздел «Повторить» с короткими сессиями из выученных слов), ежедневная цель и серия дней, необязательные напоминания через бота, раздел «Мои слова».

**12. Рукописный ввод: качество и данные.** До запуска (записанные шаблоны), M.
Распознавание сейчас настроено на шаблонах из шрифтов, а настоящий почерк на них похож хуже. Решение: инструмент записи шаблонов (27 форм, несколько вариантов), сбор рисунков пользователей с согласия для калибровки порогов по буквам, подсказка-обводка для новичков, статистика «какие буквы чаще не принимаются», запасной путь, если буква упорно не принимается (подсказка и пропуск без наказания).

**13. Доступность и устойчивость к реальным условиям.** После запуска, M.
Нет тёмной темы (Telegram передаёт тему через `themeParams`), нет отступов безопасной зоны под вырез экрана, нет тактильного отклика, анимации не отключаются при `prefers-reduced-motion`, состояние кое-где передаётся только цветом, мелкие подписи. Решение: темы из Telegram, safe-area, `HapticFeedback` на верный и неверный ответы, подписи и `aria`, предзагрузка звука и картинки следующего слова, понятное поведение без звука или микрофона (решение владельца нужно: сейчас слово без «говори» не засчитывается).

### Дизайн и контент

**14. Единый визуальный язык.** После запуска, M.
Решить источник картинок (см. открытый вопрос в `CLAUDE.md`): эмодзи как заглушка не покроют глаголы и прилагательные. Остальное: скелетоны вместо «Загрузка…» (экран не прыгает), единые состояния пустых и ошибочных экранов, анимации успеха (слово пройдено, урок сдан), страница-каталог компонентов для проверки вида, иллюстрации этапов из `design/stages/` в интерфейсе.

**15. Тексты и качество контента.** До выпуска каждой темы, M.
Все строки зашиты в компонентах (локализация потребует правок по всему коду), а правильность иврита, огласовок и транскрипции проверяет сейчас только автор. Решение: вынести строки в словарь (сейчас русский, дальше украинский и английский), единый стандарт транскрипции, поле `reviewed` у слова (кто и когда проверил), запрет публикации непроверенных слов тестом, автопроверки контента (дубликаты, длина, соответствие `niqqud` и `he`, наличие картинки и озвучки).
