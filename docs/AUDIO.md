# Озвучка слов (Google Cloud Text-to-Speech)

Файлы озвучки создаются один раз и лежат в репозитории (`apps/web/public/audio/<id слова>.mp3`), у слова в JSON появляется поле `audio`.
Приложение проигрывает файл. Если файла нет или он не проигрался, используется голос устройства.

## Что нужно один раз (вам)

1. Зайти в [Google Cloud Console](https://console.cloud.google.com/), создать проект.
2. Подключить оплату (карта нужна всегда; бесплатный лимит голосов Standard и WaveNet — 4 млн знаков в месяц, наши слова занимают десятки тысяч знаков за всё время).
3. APIs & Services → Library → «Cloud Text-to-Speech API» → Enable.
4. APIs & Services → Credentials → Create credentials → API key. В настройках ключа: API restrictions → только Cloud Text-to-Speech API.
5. GitHub → репозиторий `milav` → Settings → Secrets and variables → Actions → New repository secret: имя `GOOGLE_TTS_API_KEY`, значение — ключ.

Ключ нигде, кроме секрета GitHub, не хранится.

## Как озвучить (GitHub → Actions → «Озвучка слов» → Run workflow)

1. `voices`: покажет в логе, какие голоса he-IL доступны вашему проекту.
2. `review`: создаст для выбранного голоса по два файла на слово (без огласовок и с огласовками). Скачайте архив из блока Artifacts, послушайте, выберите голос и вариант, который произносит правильно.
3. `publish`: создаст итоговые файлы выбранным голосом и вариантом текста, запишет их в репозиторий и поле `audio` в уроках. Дальше Cloudflare сам выкатит приложение.

## Мужской и женский голос во фразах (22.10)

Решение владельца 22.10: фраза от первого лица озвучивается голосом того, кто её говорит (`docs/CONTENT.md`, «Фразы от первого лица»; в приложении настройка «Фразы-примеры от лица», `docs/SPEC.md`).

| Фраза | Файл | Голос |
|---|---|---|
| мужская (`example.speaker: "m"`), «אני הולך» | `/audio/<id слова>-phrase-m.mp3`, поле `example.audio` | мужской, вход `male_voice` (по умолчанию `he-IL-Wavenet-B`, в скрипте `--male-voice`) |
| её женский вариант (`example.female`), «אני הולכת» | `/audio/<id слова>-phrase-f.mp3`, поле `example.female.audio` | основной женский, вход `voice` (`he-IL-Wavenet-A`) |
| остальные (нейтральные и `speaker: "f"`) | `/audio/<id слова>-phrase.mp3`, поле `example.audio` | основной женский |

- Голос выбирается по заданию (`voice: "male"` или `"main"` в `tools/audio-jobs.mjs`), имя файла по роду, поэтому голоса не перепутать: тест `content/audioJobs.test.ts` проверяет, что поле `audio` каждой фразы во всех уроках совпадает с именем, которое даёт задание.
- 22.10 размечены 164 фразы (160 мужских с женским вариантом и 4 слова с постоянным говорящим), прежние файлы `-phrase.mp3` мужских фраз (162) удалены вместе с полем `audio`, новые созданы `publish` без `force`: около 160 файлов `-phrase-m` мужским голосом и столько же `-phrase-f` женским.
- **Мужской голос выбран без прослушивания** (`he-IL-Wavenet-B`, пара к основному `A`; вопрос в `docs/QUESTIONS.md`). Чтобы сравнить мужские голоса: действие `review` с голосом `he-IL-Wavenet-B` и `he-IL-Wavenet-D` (список даёт `voices`). Чтобы заменить голос: `publish` с другим `male_voice`, `force` и `kinds` нет в workflow, поэтому через `only` со списком id слов (их печатает правило или `grep -l '"speaker": "m"' content/lessons/*.json`) или локально `node tools/generate-audio.mjs --male-voice <голос> --kinds phrase --force --update-content` (нужен ключ).
- Расход: фраза 10–30 знаков, 320 фраз около 7 тысяч знаков при лимите 4 млн в месяц.
- Если файла нет, приложение читает фразу голосом устройства; его род выбрать нельзя.

## Огласовки

Иврит пишется без гласных, и по одним согласным синтезатор может ошибиться (разные слова пишутся одинаково). Поэтому у каждого слова есть поле `niqqud` — слово с огласовками, оно отправляется в синтезатор, а на экране не показывается. Тест проверяет, что это то же слово (без огласовок совпадает с `he`).

Важно: официальная документация Google не гарантирует, как голоса he-IL относятся к огласовкам, поэтому сначала делаем `review` и выбираем на слух. Огласовки в данных нужно проверить носителю языка. Для слов, где синтезатор всё равно ошибается, можно будет подобрать другой голос или другое написание текста для озвучки.

## Озвучка новых уроков

Выбор владельца (13.10): голос `he-IL-Wavenet-A`, текст с огласовками (`niqqud`). Для каждого нового урока достаточно действия `publish` с этими значениями и **без** `force`: уже готовые файлы не трогаются, создаются только недостающие, и поле `audio` дописывается в JSON урока. Запускать можно в интерфейсе GitHub (Actions → «Озвучка слов») или через REST API: `POST /repos/mosheshanin/milav/actions/workflows/generate-audio.yml/dispatches` с `ref=main` и входами `action=publish`, `voice=he-IL-Wavenet-A`, `male_voice=he-IL-Wavenet-B`, `text=niqqud`, `force=false`.

- С 14.10.2026 озвучивается всё (решение владельца): основная форма слова (`/audio/<id>.mp3`, с огласовками), три формы прилагательных (`/audio/<id>-form-f|mp|fp.mp3`, поле `audio` у формы), фраза-пример (`/audio/<id>-phrase.mp3`, поле `example.audio`), название каждой буквы (`/audio/<id буквы>.mp3`, поле `audio`, огласовки из `name.niqqud`) и слово-пример буквы, если у него нет своего файла (`/audio/<id буквы>-example.mp3`). На карточке слова рядом с формами и фразой есть кнопка «послушать»; этапы «слушай» и викторина по-прежнему работают с основной формой.
- Формы глаголов (с 14.10.2026, этап 2): до 27 файлов на глагол `/audio/<id>-form-<время>-<ключ>.mp3` (например `paal-1-write-form-past-3ms.mp3`), поле `audio` у формы внутри блока `verb`, текст с огласовками. Список заданий собирает `tools/audio-jobs.mjs`, имена проверяет `content/audioJobs.test.ts`. Расход: форма 6–12 знаков, около 270 форм на урок, это около 3 тысяч знаков при лимите 4 млн знаков в месяц. Уроков глаголов ещё нет, файлов тоже; после появления «Пааль 1» запустить `publish` как обычно. Объём файлов см. вопрос 30 в `docs/QUESTIONS.md`.
- Уроки «Пааль 1–3» озвучены сразу, до проверки носителем (14.10): 870 файлов (30 инфинитивов, 810 форм, 30 фраз). Исправленную носителем форму переозвучить точечно: `--only <id слова> --force` (в workflow «Озвучка слов» поле `only` и галочка `force`, с 16.10) (все формы этого глагола) или `--kinds form`.
- Уроки «Пиэль 1–3» озвучены так же сразу (15.10): 870 файлов `piel-*`. Всего в `apps/web/public/audio` 2165 файлов, 19,7 МБ (вопрос 30 в `docs/QUESTIONS.md`).
- У фраз огласовок обычно нет, в синтезатор уходит иврит без них: произношение может быть неточным. С 22.10 у фразы и её женского варианта есть необязательное поле `niqqud` (можно огласовать только спорное слово): если оно есть, в синтезатор уходит оно. Если на слух неверно, его и добавляют, или подбирают другое написание. Первое прослушивание сделает владелец; `--only <id слова>` перезапишет один элемент (с `--force`), `--kinds phrase` ограничит видом.
- Формы с гереш (урок `alphabet-6`: ג׳ ז׳ צ׳) и их слова-примеры: в синтезатор знак `׳` уходит обычным апострофом `'` (функция `forSpeech` в `tools/generate-audio.mjs`), потому что так пишут иврит в текстах для речи. Проверить на слух, что слышно «дж», «ж», «ч» (ג׳ינס, ז׳קט, צ׳יפס); если голос игнорирует знак, переозвучить слово другим написанием через `--only <id> --force`.
- Если носитель исправил слово, удалить файл `apps/web/public/audio/<id>.mp3` и снова запустить `publish` (без `force`), либо `force` для всех слов сразу.
- Кэш (15.10): файлы `/audio/*` отдаются с `Cache-Control: public, max-age=86400` (`apps/web/public/_headers`), чтобы «послушать» срабатывало без запроса к серверу. Поэтому переозвученный файл с тем же именем дойдёт до ученика, который уже слушал старый, в течение суток. Приложение также подгружает файл заранее, когда кнопка «послушать» появляется на экране (`primeAudio` в `apps/web/src/lib/audio.ts`).
- Порядок для новых слов: сначала проверка носителем, потом озвучка (иначе исправленное слово придётся озвучивать заново). Для 130 слов тем «Животные 2–3», «Еда», «Семья», «Дом и мебель», «Цвета» озвучка сделана сразу, до проверки: слова, которые носитель исправит, нужно перезаписать.
- Расход бесплатного лимита Google: слово с огласовками занимает 10–15 знаков, 130 слов это около 2 тысяч знаков при лимите 4 млн знаков в месяц.
