# Деплой на Cloudflare (бесплатный тариф)

Приложение целиком (фронтенд и API) работает как один Worker `milav`. Свой сервер, SSH и Node.js на вашем компьютере не нужны:
сборка и публикация идут в облаке Cloudflare при каждом пуше в `main`.

## Как идёт выкладка

Пуш в `main` запускает две независимые цепочки:

| Где | Что делает | Блокирует выкладку? |
|---|---|---|
| Cloudflare (Workers Builds) | 1. `npm run check`: типы, тесты, сборка. 2. Миграции базы. 3. Публикация Worker | **Да**: если любой шаг упал, новая версия не выходит, на сайте остаётся предыдущая |
| GitHub Actions (`.github/workflows/ci.yml`) | То же самое (типы, тесты, сборка) и сквозной тест в Chromium, скриншоты сохраняются как артефакт | Нет, но красный крестик у коммита значит «чинить сейчас» |

Тест `apps/api/src/wrangler-config.test.ts` входит в `npm test`, поэтому выкладка с тестовым входом (`ALLOW_DEV_AUTH` вне `env.local`) невозможна: сборка в Cloudflare упадёт.

Сквозной тест в Cloudflare не запускается (там нет Chromium), его результат виден только в GitHub Actions.

## Настройка автодеплоя (один раз)

Worker `milav` → Settings → Builds (подключение к GitHub-репозиторию `mosheshanin/milav`):

| Поле | Значение |
|---|---|
| Production branch | `main` |
| Root directory | `/` (корень репозитория) |
| Build command | `npm run check` |
| Deploy command | `npx wrangler d1 migrations apply milav-db --remote && npx wrangler deploy` |

`npm run check` — это `npm run typecheck && npm test && npm run build` одной командой (если удобнее, можно вписать длинную форму).

Конфигурация Worker лежит в корне: `wrangler.jsonc` (имя `milav`, точка входа `apps/api/src/index.ts`, статика `apps/web/dist`).
Имя в `wrangler.jsonc` должно совпадать с именем Worker в панели Cloudflare.

### Права токена сборки на базу (обязательный шаг, иначе деплой упадёт)

Токен, который Cloudflare создаёт для сборок сам, по документации не включает права на D1 (только Workers Scripts, KV и R2). Команда миграций без них завершится ошибкой доступа, и выкладка остановится. Один раз добавьте право:

1. Cloudflare → иконка профиля → My Profile → API Tokens.
2. Найдите токен, который использует сборка Worker `milav` (имя видно в Worker → Settings → Builds → API token).
3. Edit → добавьте разрешение Account → D1 → Edit → Continue to summary → Update Token.
4. Worker `milav` → Builds → вручную запустите повторную сборку последнего коммита.

Названия пунктов в панели могут слегка отличаться, смысл тот же. В логе сборки после шага миграций должно быть «No migrations to apply» (или список применённых), а затем успешный `wrangler deploy`. Первую выкладку после изменения настроек стоит посмотреть в логе целиком.

## Правила миграций (`migrations/`)

Миграции применяются автоматически **до** публикации нового кода, а откат кода базу не откатывает. Поэтому:

- Миграции только добавляют: новая таблица, новая колонка со значением по умолчанию, новый индекс. Старый код продолжает работать на новой схеме.
- Удалять и переименовывать колонки и таблицы нельзя одной миграцией. Делаем в два выпуска: сначала код перестаёт ими пользоваться и выкатывается, в следующем выпуске отдельная миграция удаляет.
- Уже применённый файл миграции не правим, любое изменение схемы — новый файл со следующим номером (`0002_...sql`).
- Новую миграцию проверяем локально до пуша: `npx wrangler d1 migrations apply milav-db --local --env local`.

## Как выкатывать

1. Перед пушем: `npm run check` (типы, тесты, сборка). Сквозной тест по желанию, см. ниже.
2. Коммит и пуш в `main`.
3. Через несколько минут: у коммита на GitHub зелёная галочка (вкладка Actions), в Cloudflare у Worker `milav` на вкладке Deployments появилась новая версия, `https://milav.<ваш-поддомен>.workers.dev/api/health` отвечает `{"ok":true,...}`.

## Как откатывать

Основной способ: **revert коммита**. Откат тоже проходит через проверки и миграции.

```
git revert <хеш плохого коммита>
git push origin main
```

Если сайт сломан прямо сейчас и нужно мгновенно: Cloudflare → Workers & Pages → `milav` → Deployments → три точки у нужной версии → Rollback. Версия возвращается сразу, но:

- база данных не откатывается (данные и схема остаются как есть), поэтому правило «миграции только добавляют» важно;
- после быстрого отката обязательно сделайте revert коммита в `main`, иначе следующий пуш снова выложит сломанный код;
- доступны 100 последних версий.

## Секреты

Worker `milav` → Settings → Variables & Secrets → секрет `BOT_TOKEN` (токен бота от @BotFather), уже добавлен.
В репозиторий токен не попадает.

**Владелец (панель администратора, запись шаблонов, настройка бота):** секрет `ADMIN_IDS` (тип **Secret**, не Text) со списком Telegram id через запятую, например `123456789`. Прежний секрет `TEMPLATE_RECORDER_IDS` читается так же (владельцы это id из обоих), поэтому переименовывать его не обязательно. Владелец всегда администратор: из панели его убрать нельзя, даже при ошибке в базе. Остальных администраторов и проверяющих владелец добавляет в самой панели («Команда»), без секретов и выкладки. Свой id каждый видит в приложении: «Настройки» → «Аккаунт». Для локальной разработки id тестового пользователя `1001` прописан в `env.local` в `wrangler.jsonc` (тест `wrangler-config.test.ts` следит, чтобы в боевом конфиге его не было).

Для озвучки: секрет `GOOGLE_TTS_API_KEY` в GitHub (Settings → Secrets and variables → Actions), см. [`AUDIO.md`](./AUDIO.md).

## Бот (вебхук, ответ на `/start`)

Код: `apps/api/src/bot.ts`, маршрут `POST /api/bot/webhook`.

- **Что отвечает.** `/start`: приветствие по имени и кнопка «📚 Открыть Milav» (открывает мини-приложение). `/help`: как заниматься. Любой другой текст: «все занятия в приложении» и та же кнопка. В группах и каналах бот молчит (кнопка мини-приложения в сообщении работает только в личном чате). Ответ уходит прямо в ответе на вебхук, без исходящих запросов и без записи в D1.
- **Защита.** Telegram присылает заголовок `X-Telegram-Bot-Api-Secret-Token`; секрет выводится из `BOT_TOKEN`, отдельный секрет не нужен. Без верного заголовка ответ 401.
- **Регистрация вебхука автоматическая.** Когда приложение открывает владелец (id из секрета `TEMPLATE_RECORDER_IDS`), Worker в фоне проверяет вебхук (`getWebhookInfo`) и при необходимости регистрирует его (`setWebhook` с секретом), ставит команды `/start`, `/help` и описание бота, если в BotFather оно пустое. Проверка идёт не чаще раза на экземпляр Worker. Расписание (cron) не используем: на бесплатном тарифе их 5 на весь аккаунт Cloudflare (лимиты на 15.10.2026), а в аккаунте есть другие проекты.
- **Смена токена.** В адресе вебхука есть метка `?v=…` (отпечаток токена, не секрет). После смены `BOT_TOKEN` в Cloudflare достаточно открыть приложение владельцем: адрес не совпадёт, вебхук перерегистрируется с новым секретом.
- **Чужой вебхук.** Если у бота уже стоит вебхук на другой адрес (старый сервер), Worker его не перезаписывает и пишет `bot_webhook_foreign` с хостом. Снять чужой вебхук: открыть в браузере `https://api.telegram.org/bot<ТОКЕН>/deleteWebhook` (токен из @BotFather, ссылку никому не пересылать), затем открыть приложение.
- **Проверить.** Написать боту `/start`. Если молчит: открыть приложение (владельцем), подождать минуту и снова `/start`; в журналах (`evt = bot_setup_error`, `bot_webhook_foreign`, `bot_webhook_error`) будет причина.
- **Дальше.** Для платежей Stars в `BOT_ALLOWED_UPDATES` добавится `pre_checkout_query`; самонастройка заметит разницу и перерегистрирует вебхук сама. Напоминания от бота (вопрос 41) потребуют исходящих сообщений и расписания.

## Ручной деплой и локальная разработка (по желанию, нужен Node.js)

```
npm install
npm run dev:api    # Worker на http://localhost:8787 (раздаёт собранный apps/web/dist)
npm run dev:web    # фронтенд на http://localhost:5173, запросы /api уходят на Worker
npm run deploy     # сборка и ручная публикация (после npx wrangler login), миграции не применяет

# миграции боевой базы вручную (при обычной выкладке это делает Cloudflare):
npx wrangler d1 migrations apply milav-db --remote
```

Для локальных секретов скопируйте `apps/api/.dev.vars.example` в `.dev.vars` в корне репозитория.

## Проверки

```
npm run check       # типы, юнит-тесты и сборка одной командой (то же запускает Cloudflare)
npm run typecheck   # только типы во всех пакетах
npm test            # только юнит-тесты (общие правила, контент, API на настоящем SQLite, лимиты, заголовки, викторина, распознавание букв, защитный тест конфигурации)
```

Сквозная проверка в браузере (Chromium на размере телефона, урок и викторина целиком). В GitHub Actions она идёт сама (работа «Сквозной тест»); локально:

```
npm run build
npx wrangler d1 migrations apply milav-db --local --env local
npm run dev:api                      # в одном окне
node tools/e2e-lesson.mjs e2e-shots  # в другом, скриншоты попадут в e2e-shots/
```

Урок для прохождения выбирается переменной `E2E_LESSON` (по умолчанию `animals-1`). В CI дополнительно идут `colors-1` (прилагательные: строка форм на карточке) и `family-2` (слова без картинок: запасной вариант), каждый около 2,5 минут; работа «Сквозной тест» ограничена 50 минутами (весь прогон идёт 33–36 минут, см. `timeout-minutes` в `.github/workflows/ci.yml`). Локально: `E2E_LESSON=colors-1 node tools/e2e-lesson.mjs e2e-shots`.

Алфавит проверяется отдельным сценарием (`node tools/e2e-alphabet.mjs e2e-shots`, тот же запущенный Worker; урок выбирается переменной `E2E_ALPHABET`, по умолчанию `alphabet-1`): новичок на главной видит «Алфавит» первым и «Начать», проходит урок из букв (слушай, пиши, печатай, без «говори»), сдаёт викторину из 20 вопросов четырёх типов; пятая ошибка прерывает викторину и ничего не сохраняет; запросами без приложения нельзя отметить «говори» у буквы и засчитать «пиши» или «печатай» без доказательства. В CI это отдельные шаги «Сквозной тест алфавита» для всех пяти уроков (`E2E_ALPHABET=alphabet-1` … `alphabet-5`, в 3–5 конечные формы). Для уроков 2–5 сценарий открывает урок со списка на главной: «Продолжить» у новичка ведёт в первый урок алфавита.

Проверки контента (`npm run validate:content`, входят в `npm test`, то есть и в сборку Cloudflare) описаны в `docs/CONTENT.md`: сломанный урок или забытая команда `npm run content:index` не выкладываются.

Там же проверка экрана записи шаблонов букв (`node tools/e2e-record.mjs e2e-shots`, нужен тот же запущенный Worker): чужой не получает доступ, владелец записывает 5 вариантов формы, замена, удаление, предупреждение «похоже на другую букву», перезагрузка.

Панель администратора: `node tools/e2e-admin.mjs e2e-shots/admin` (тот же Worker; владелец 1001, ученик 1002). Сценарий сам очищает `app_config`, `staff`, `admin_log` и `daily_stats` в локальной базе до и после.

Скрипт ищет Chromium в каталоге из `PLAYWRIGHT_BROWSERS_PATH` (по умолчанию `/opt/pw-browsers`). Установить браузер: `npx playwright-core install chromium`.

Локально открыть приложение вне Telegram можно по адресу `http://localhost:8787/?dev=1001` (номер задаёт тестового пользователя).
Тестовый вход работает только в `env.local` (`ALLOW_DEV_AUTH` в `wrangler.jsonc`); на боевом Worker его нет, и тест `wrangler-config.test.ts` следит, чтобы так и осталось.

## Лимиты запросов и заголовки безопасности

**Лимиты на одного пользователя** (считает Worker, таблица `rate_limits` в D1, миграция `0002`; окна фиксированные, минута и сутки по UTC). Значения лежат в одном месте, `RATE_LIMITS` в `packages/shared/src/constants.ts`:

| Действие | В минуту | В сутки | Зачем |
|---|---|---|---|
| Проверка произношения (`/api/speech/check`) | 20 | 300 | Дорогой вызов Whisper, у Workers AI бесплатная суточная квота на всех |
| Отметка этапов (`/api/progress/stage`) | 60 | 1500 | В уроке 10 слов по 3 отметки; защита базы от потока запросов |
| Начало викторины (`/api/quiz/start`) | 10 | 100 | Защита базы; ответы на вопросы отдельным лимитом не считаются: каждый вопрос принимается один раз |
| Запись шаблонов букв (`/api/templates`, только владелец) | 120 | 3000 | Защита базы; на полный набор нужно 135 записей |

Сверх лимита сервер отвечает `429` с `retryAfter` (секунд до конца окна) и заголовком `Retry-After`, приложение показывает «Слишком много попыток подряд. Подождите N с». Запросы без входа лимитами не считаются. Если лимиты мешают настоящим ученикам, поднимите числа в `RATE_LIMITS` и выкатите как обычно (миграция не нужна).

Цена: каждый ограниченный запрос это ещё одна запись строки в D1 (строка на пользователя и действие обновляется на месте, не растёт). Бесплатный лимит D1 на запись в сутки общий для всего приложения, расход смотрите в панели Cloudflare (Storage & Databases → D1 → milav-db → Metrics).

**Заголовки безопасности.** Страницы и файлы приложения получают заголовки из `apps/web/public/_headers`, ответы API из `apps/api/src/security.ts`:

- CSP строгая: скрипты только свои и `https://telegram.org`, без inline и eval; всё остальное (стили, шрифты, картинки, звук, запросы) только со своего адреса; встраивать приложение можно только в Telegram (`frame-ancestors`).
- `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy` (микрофон только для себя), у API ещё `Cache-Control: no-store`.
- Тест `apps/api/src/headers-file.test.ts` не даёт ослабить политику (unsafe-inline, unsafe-eval, чужие скрипты), а сквозной тест падает, если приложение нарушает собственную CSP.

Если после выкладки в Telegram что-то перестало работать (пропали стили, шрифты, картинки, не грузится скрипт), причина почти наверняка в CSP: откройте консоль браузера, там видно «Refused to ... because it violates the following Content Security Policy». Откат: revert коммита, который менял `_headers`.

## Наблюдаемость (журналы, ошибки, воронка)

Сделано 15.10.2026 (ROADMAP п. 9). Всё пишется в **Workers Logs**, в базу D1 ничего не попадает (её бесплатный лимит записей нужен урокам). Настраивать ничего не нужно: журналы включены в `wrangler.jsonc` (`observability`), тест `wrangler-config.test.ts` не даёт их случайно выключить.

**Где смотреть.** Панель Cloudflare → Workers & Pages → `milav` → **Observability** (вкладка Events или Query Builder). У каждой записи приложения есть поле `evt`: фильтр `evt = client_error` покажет ошибки на телефонах. Записи хранятся **3 дня**.

**Что пишется:**

| `evt` | Уровень | Когда | Поля |
|---|---|---|---|
| `server_error` | error | необработанная ошибка сервера (ученик видит «internal_error») | `method`, `path`, `message`, `stack` |
| `client_error` | error | ошибка в приложении на телефоне: скрипт, промис, падение экрана | `source` (`error` / `rejection` / `render`), `message`, `stack`, `screen`, `platform`, `tgVersion`, `app` (коммит сборки), `uid` |
| `client_app_crash` | info | экран упал, ученик видит «Что-то пошло не так» и кнопку «Перезапустить» | `screen`, `platform`, … |
| `client_mic_problem` | info | не включился микрофон | `detail` (`denied` / `unsupported`), `platform`, … |
| `whisper_error` | error | Workers AI не распознал запись (лимит, таймаут, формат) | `message` |
| `health_db_error` | error | `/api/health` не достучался до базы | `message` |
| `app_open` | info | запуск приложения (запрос профиля) | `uid`, `tz`, `points` |
| `word_done` | info | слово или буква пройдены по всем этапам | `uid`, `lesson`, `item`, `points` |
| `speech` | info | проверка произношения | `uid`, `word`, `where` (`study` / `quiz`), `match`, `heard` (что услышал Whisper), `he` (ожидаемое слово), `cost` (расстояние до него: 0 точно, 2 одна правка, не меняющая звук, 3 одна обычная ошибка), `budget` (допуск: 0, 2 или 3), `closest` (ближайший вариант: вся фраза или одно слово из неё) |
| `speech_failed` | warn | распознаватель не ответил | `uid`, `word`, `where`, `bytes` |
| `quiz_start` / `quiz_end` | info | начало и конец викторины | `uid`, `lesson`; у конца `outcome` (`passed` / `failed` / `aborted`), `correct`, `mistakes` |
| `stage_rejected` | warn | сервер не принял этап «пиши» или «печатай» | `uid`, `lesson`, `item`, `stage`, `error`, `failed` (номера букв) |
| `rate_limited` | warn | ученик упёрся в лимит запросов | `uid`, `action`, `retryAfter` |
| `bot_message` | info | бот ответил на сообщение в личном чате | `uid`, `cmd` (`start` / `help` / другая команда / `text`) |
| `bot_webhook_set` | info | Worker зарегистрировал вебхук бота | `previous` (`none` / `own`) |
| `bot_webhook_foreign` | warn | у бота чужой вебхук, Worker его не трогает | `host` |
| `bot_webhook_error` | warn | Telegram сообщает об ошибке доставки на наш вебхук | `error` |
| `bot_setup_error` | error | самонастройка бота не удалась (сеть, ответ Telegram) | `message` |

Кроме того, Cloudflare сам пишет запись о каждом запросе к `/api/*`: адрес, код ответа, время процессора (видно, если упираемся в 10 мс бесплатного тарифа).

**Готовые вопросы к журналу** (Query Builder):
- Сколько людей занималось сегодня: `evt = app_open`, Count Distinct по `uid`.
- Где бросают: число `app_open`, `word_done`, `quiz_start`, `quiz_end` за день.
- Какие слова Whisper слышит плохо: `evt = speech`, `match = false`, группировка по `word` (поле `heard` показывает, что он услышал).
- Правильно ли настроен допуск речи: `evt = speech`, `match = false`, смотреть `he` рядом с `heard`. Если `cost` чуть больше `budget` (например, `cost = 4` при `budget = 2`) и по буквам видно, что звучит так же, допуск надо расширить; если принято `match = true` с `cost` равным `budget`, а слово другое, ужесточить. Записи хранятся 3 дня, поэтому смотрим после каждой пробной раздачи ученикам. Отчёт по самим словам уроков (какие пары слов правило считает одинаковыми): `npm run speech:collisions` (`-- --all` для всех тем).
- У кого не работает микрофон: `evt = client_mic_problem`, группировка по `platform` и `detail`.
- Что сломалось у учеников: `evt = client_error`, группировка по `message`; поле `app` говорит, в какой сборке.

**Как приложение отправляет отчёты.** `apps/web/src/lib/telemetry.ts` ловит необработанные ошибки и промисы, `components/ErrorBoundary.tsx` ловит падение экрана. Отчёт уходит на `POST /api/client-log` и никогда не мешает ученику: за запуск не больше 10 отчётов, одинаковые не повторяются, бесполезные ошибки браузера («Script error.», «ResizeObserver loop») не отправляются. Сервер принимает только известные события (`CLIENT_EVENTS` в `packages/shared/src/telemetry.ts`), обрезает поля и убирает переводы строк, тело до 4 КБ, не больше 30 отчётов в минуту с одного адреса (в памяти Worker, без D1). Вход необязателен; если подпись Telegram верна, в запись попадает `uid`.

**`/api/health`** теперь проверяет и базу: `{"ok":true,"db":"ok"}`, а если база не отвечает, код **503**. С 01.09.2026 Cloudflare на бесплатном тарифе **отклоняет запросы к D1 после дневного лимита** чтений или записей (до полуночи UTC) и присылает письмо на почту аккаунта. В этом случае приложение не работает целиком: следите за письмами Cloudflare и за расходом (Storage & Databases → D1 → milav-db → Metrics). По желанию можно поставить бесплатный внешний монитор (например, UptimeRobot) на `https://milav.moshemadwords.workers.dev/api/health`: он пришлёт письмо, когда ответ не 200.

**Лимиты журналов.** Бесплатно 200 000 записей в сутки, хранение 3 дня. С 01.12.2026 Cloudflare переходит на новую схему: бесплатно 0,5 ГБ в сутки, хранение 7 дней, после лимита запись прекращается до полуночи UTC (приложение продолжает работать). Оценка: около 150 записей на активного ученика в день, то есть журнал выдержит около 1 300 учеников в сутки, а D1 упрётся раньше (около 590, вопрос 26). Если журнала станет не хватать, уменьшите `head_sampling_rate` в `wrangler.jsonc` (например, `0.5` пишет половину запросов).

**Приватность.** В записях есть Telegram id (`uid`), часовой пояс и то, что распознал Whisper. В автоматической записи о запросе Cloudflare может сохранить заголовки, в том числе подпись входа Telegram (она действует сутки). Журналы видит только владелец аккаунта Cloudflare, хранятся 3 дня. Упомянуть это в политике конфиденциальности (ROADMAP п. 4).

Действует без выкладки, на всех экземплярах Worker не дольше чем через минуту; изменение пишется в журнал панели. Пока в панели ничего не меняли, действует переменная `LEADERBOARD_ENABLED` в `wrangler.jsonc` (`"1"` = «Все»; **таблица включена с 14.10.2026 по решению владельца, без отдельной политики конфиденциальности**, ROADMAP п. 4). Когда таблица выключена для человека, вступить нельзя (403 `feature_disabled`), кнопок «Таблица» нет, `/api/leaderboard` отвечает 404; бейджи, ритм, цель дня и сравнение с ровесниками работают; данные участников сохраняются. Потолка очков нет: смотреть запрос «подозрительно быстрый набор очков» ниже.

**Лимиты новых маршрутов** (в `RATE_LIMITS`): `PUT /api/settings` 20 в минуту и 200 в сутки, `POST /api/achievements/seen` 30 и 300. Читающие маршруты (`GET /api/achievements`, `/api/leaderboard`, `/api/cohort`) через D1 не ограничиваются: лимитер пишет строку на каждый запрос. Встроенный Rate Limiting binding Cloudflare не используем: в документации для бесплатного тарифа подтверждения нет (проверено 14.10.2026).

**Расход записей D1.** Каждое завершённое слово пишет две строки (счётчики и ритм), урок из 10 слов это около +20 к прежним 145 на ученика в день; снимки таблицы пишутся не чаще раза в 10 минут (неделя) и 30 минут (всё время) и только при просмотрах. Первые дни после выкладки смотреть «Rows written» на панели D1: ожидание около 170 строк на активного ученика в день (потолок около 590 активных учеников в сутки). Одноразовый пересчёт старых пользователей (первый вход после выкладки) даёт до 12 записей на человека и сотни чтений. Если записи не хватает, первым делом копить статистику вопросов викторины в сессии (раздел «Викторина на сервере»).

Запросы для консоли D1 (Storage & Databases → D1 → milav-db → Console):

```sql
-- Сколько человек участвует в таблице.
SELECT COUNT(*) AS participants FROM user_stats WHERE lb_optin = 1 AND lb_banned = 0;

-- Подозрительно быстрый набор очков (потолка очков в таблице нет, решение владельца): слов за день занятий.
SELECT user_id, words_done + letters_done AS total, active_days,
       ROUND(1.0 * (words_done + letters_done) / MAX(active_days, 1), 1) AS per_day, lb_week_points
FROM user_stats ORDER BY per_day DESC LIMIT 20;

-- Аудит счётчиков: очки в user_stats должны совпадать с числом пройденных слов и букв в word_progress.
SELECT s.user_id, s.words_done + s.letters_done AS counter, COUNT(w.word_id) AS actual
FROM user_stats s LEFT JOIN word_progress w ON w.user_id = s.user_id AND w.completed_at IS NOT NULL
GROUP BY s.user_id HAVING counter != actual LIMIT 50;

-- Сколько раз выдан каждый бейдж.
SELECT badge_id, COUNT(*) AS n FROM user_badges GROUP BY badge_id ORDER BY n DESC;
```

**Бан в таблице** (имя нарушает правила, накрутка): `UPDATE user_stats SET lb_banned = 1 WHERE user_id = <id>;` человек сразу исчезает из таблицы и из чтения, сам он этого не видит; вернуть: `lb_banned = 0`.

**Починка счётчиков.** Если аудит показал расхождение: `DELETE FROM user_stats WHERE user_id = <id>;`. Строка пересоздастся при следующем входе пересчётом из `word_progress`, `lesson_passed` и `quiz_attempts`. Бейджи не теряются (`user_badges` не трогаем), но сбрасываются ритм недели, цель дня, часовой пояс и участие в таблице: человеку придётся вступить заново.

**Что проверить на телефоне в настоящем Telegram** после выкладки: `docs/GAMIFICATION.md`, раздел 13, и вопрос 23 в `docs/QUESTIONS.md`.

## Викторина на сервере

Вопросы викторины выдаёт Worker, каждый ответ проверяет он же, итог считает и пишет он (миграция `0003_quiz_sessions.sql`, код `apps/api/src/quizSession.ts`, маршруты в `apps/api/src/app.ts`):

- `POST /api/quiz/start` (урок должен быть пройден целиком) → id сессии и 25 вопросов;
- `POST /api/quiz/answer` (выбор, письмо, отказ от вопроса) и `POST /api/quiz/speech?sessionId=&index=` (запись голоса, проверка Whisper) → вердикт; на последнем вопросе в ответе уже лежит итог.

Таблица `quiz_sessions` хранит одну строку на пользователя (новый старт её заменяет), поэтому не растёт. Каждое изменение сессии меняет случайную метку `rev`, и запись проходит только с прежней меткой: два одновременных ответа на один вопрос не засчитаются оба. Итог (`quiz_attempts`, `lesson_passed`) пишется в той же транзакции, что и последний ответ.

Цена: одна викторина это около 55 записей в D1 (по две на ответ: сессия и статистика, плюс начало, итог и лимит). Бесплатная квота на запись в сутки общая; при 100 000 записей в сутки это порядка 1800 викторин в сутки. Если квота станет узким местом, статистику можно копить в сессии и писать одним пакетом в конце, а `getTotals` заменить счётчиками (ROADMAP п. 6).

**Статистика по вопросам.** Слова, которые чаще всего отвечают неверно (нужны хотя бы 20 вопросов, чтобы цифра что-то значила). Выполнять в Cloudflare: Storage & Databases → D1 → milav-db → Console:

```sql
SELECT word_id, question_type, asked, correct, ROUND(100.0 * correct / asked) AS percent
FROM question_stats WHERE asked >= 20 ORDER BY percent ASC LIMIT 30;
```

Низкий процент у «произнеси» при нормальном у других типов указывает на плохую озвучку или распознавание этого слова; низкий у «напиши» на конкретную букву в слове на шаблоны букв (ROADMAP п. 12).

## Шаблоны букв (запись и калибровка)

Рукописный ввод проверяется по шаблонам: 270 из шрифтов (`baseTemplates.json`) и записанные владельцем, по 5 вариантов на каждую из 27 форм (`ownTemplates.json`). Приложение и сервер берут один и тот же набор одной выкладкой.

**Один раз настроить**

1. Миграция `0004_letter_templates.sql` применяется сама при выкладке (таблица `letter_templates`, приёмник рисунков).
2. С 15.10.2026 запись открывается из панели администратора: «Настройки» → «Панель администратора» → «Шаблоны букв» (доступ у всех администраторов). Прежний путь тоже работает: параметр запуска `startapp=record`. Кнопка меню бота параметр передать не может, нужна прямая ссылка: в @BotFather `/newapp` (или Bot Settings → Configure Mini App для главного приложения) и ссылка вида `https://t.me/<бот>/<имя_приложения>?startapp=record` (для главного приложения `https://t.me/<бот>?startapp=record`). Открывайте её с телефона, с которого будете рисовать.
3. Откройте ссылку. Если секрет ещё не задан, экран скажет «Нет доступа» и покажет ваш Telegram id. Занесите его в секрет `ADMIN_IDS` (или прежний `TEMPLATE_RECORDER_IDS`) в Cloudflare (Worker `milav` → Settings → Variables & Secrets → Add → тип Secret) и откройте ссылку снова. Дополнительного деплоя не нужно.

**Как записывать.** Сетка из 27 форм (буквы идут справа налево, как в иврите), у каждой счётчик «записано из 5». Кнопка «Следующая незаписанная» ведёт по порядку. На карточке формы пять ячеек вариантов: нарисуйте форму между линиями и нажмите «Сохранить», следующий вариант выбирается сам. Нарисовать поверх записанного заменяет его, «Удалить этот вариант» очищает ячейку. Рисуйте как пишете в жизни, чуть по-разному: чем больше разных начертаний, тем лучше распознавание. Линия на холсте 16 px, как штрих шрифта подсказки и как на этапе «пиши» у учеников; превью в ячейках вариантов рисуются той же толщиной (у маленьких форм не толще пятой части ячейки). На распознавание толщина не влияет. Если рисунок по текущим шаблонам больше похож на другую букву, он всё равно сохраняется, но с предупреждением (это подсказка, а не отказ: у владельца почерк может быть своим).

**Что дальше (делает Claude, один раз после записи всех 135)**

```
npx wrangler d1 execute milav-db --remote --json --command "SELECT letter, slot, strokes FROM letter_templates ORDER BY letter, slot" > rows.json
npm run templates -- import rows.json   # data/handwriting/own-strokes.json (исходные штрихи, они в git)
npm run templates -- build              # packages/shared/src/handwriting/ownTemplates.json
npm run templates -- report             # оценка: по буквам, путаницы, какие чужие буквы принимаются
npm run templates -- report fonts       # то же без шаблонов владельца (для сравнения)
npm run templates -- sweep              # перебор maxDistance и slack
```

Оценка честная: каждый рисунок проверяется против шрифтов и остальных рисунков владельца без самого себя. Пороги (`RECOGNIZER` в `packages/shared/src/handwriting/recognizer.ts`) меняются по отчёту, затем `npm run check` и обычная выкладка. Таблица `letter_templates` остаётся только приёмником: источником истины служат файлы в репозитории.

**Проверка на бесплатном тарифе.** Серверная проверка слова из пяти букв занимает около 2 мс (лимит 10 мс процессорного времени на запрос). После добавления шаблонов владельца (405 вместо 270) стоит ещё раз открыть этап «пиши» на телефоне и проверить, что слово из 5–6 букв сохраняется без ошибки 1102 (`Worker exceeded CPU time limit`) в логах.

## Напоминания от бота

Описание: `docs/REMINDERS.md` (раздел «Этап 1: как сделано»).
