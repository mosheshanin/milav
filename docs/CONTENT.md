# Контент: формат урока, правила и как добавить урок

Контент живёт в `content/` как данные (JSON), а не в коде. Продуктовые решения: `docs/SPEC.md` (разделы «Контент», «Слово», «Урок»), решения владельца: `CLAUDE.md`. Здесь техническое описание формата и порядок работы.

## Иерархия и правила

- Раздел → тема → урок → слова. Разделы: Существительные (`nouns`), Глаголы (`verbs`), Прилагательные (`adjectives`).
- В уроке ровно 10 слов (`WORDS_PER_LESSON`).
- В каждой теме первые 3 урока бесплатные, остальные платные (`FREE_LESSONS_PER_TOPIC`), независимо от числа уроков.
- Тема не хранится отдельным файлом: она задаётся полями `topicId` (постоянный латинский ключ) и `topic` (название на экране) в каждом уроке. Порядок тем на главной сейчас определяется ключом темы и номером урока (`content/registry.ts`); явный порядок и манифест появятся вместе с платными уроками (ROADMAP п. 5).
- **id слов не меняем никогда**: прогресс пользователей привязан к ним, сервер находит слово по id (`findWord`).
- Тема «Алфавит» устроена иначе: раздел `alphabet`, элементы урока не слова, а буквы (см. «Уроки алфавита» ниже).

## Файлы и команды

| Что | Где |
|---|---|
| Урок | `content/lessons/<id урока>.json` (один урок: один файл, имя файла равно `id`) |
| Схема формата | `content/schema.json` (в уроке `"$schema": "../schema.json"`: редактор подсказывает поля) |
| Правила, которых нет в схеме | `content/rules.ts` (транскрипция, правила набора) |
| Реестр уроков в приложении | `content/registry.ts` (создаётся командой, руками не правится) |
| Картинки слов | `apps/web/public/words/` |
| Озвучка | `apps/web/public/audio/` (создаёт workflow, `docs/AUDIO.md`) |

```
npm run content:new -- --topic-id animals --number 2 --title "Дикие животные" --keys wolf,fox,bear,deer,monkey,camel,giraffe,zebra,tiger,crocodile
npm run content:new -- --topic-id alphabet --number 2 --title "Название урока"   # урок алфавита: буквы заданы, --keys не нужен
npm run content:index          # обновить реестр после добавления или удаления файла урока
npm run validate:content       # все проверки контента (входит в npm test и npm run check)
npm run content:report         # сводка: темы и алфавит, непроверенные слова и буквы, без картинки и озвучки
npm run content:report -- --list   # слова и буквы для носителя языка: огласовки, транскрипция, фразы
```

## Формат урока

| Поле | Тип | Правило |
|---|---|---|
| `id` | строка | `<topicId>-<номер>`, например `animals-1`; совпадает с именем файла |
| `topicId` | строка | постоянный ключ темы, латиница в нижнем регистре, например `animals` |
| `section` | `nouns` / `verbs` / `adjectives` | раздел |
| `topic` | строка | название темы на экране, одинаковое во всех уроках темы |
| `number` | целое | номер урока в теме, подряд с 1 |
| `free` | boolean | `true` у уроков 1–3, у остальных `false` |
| `title` | строка | название урока |
| `words` | массив | ровно 10 слов |

## Формат слова

Общие поля:

| Поле | Обязательно | Правило |
|---|---|---|
| `id` | да | `<id урока>-<ключ слова>`, например `animals-1-cat`; уникален во всём наборе |
| `he` | да | иврит только буквами, без огласовок; конечные формы (ך ם ן ף ץ) только в конце слова |
| `niqqud` | да | то же слово с огласовками; без огласовок совпадает с `he`. Уходит в синтезатор, на экране не показывается |
| `translit` | да | транскрипция кириллицей по стандарту ниже |
| `ru` | да | перевод на русский |
| `reviewed` | да | `false`, пока не проверил носитель языка; после проверки `{ "by": "Имя", "at": "2026-10-13" }` |
| `image` | нет | `/words/<id слова>.svg` (или png, webp); без картинки карточка показывает запасной вариант |
| `audio` | нет | `/audio/<id слова>.mp3`, заполняет скрипт озвучки. Так же озвучиваются формы прилагательных (`forms.*.audio`, `/audio/<id>-form-<f|mp|fp>.mp3`), формы глаголов (`verb.<время>.<ключ>.audio`, `/audio/<id>-form-<время>-<ключ>.mp3`) и фраза (`example.audio`, `/audio/<id>-phrase.mp3`) |

Поля по разделам:

| Раздел | Основная форма в `he` | `gender` | `example` | `forms` |
|---|---|---|---|---|
| Существительные | единственное число | обязателен: `m` или `f` | обязательна | нельзя |
| Глаголы | инфинитив (לכתוב, «писать») | нельзя (род в формах) | обязательна, фраза с глаголом в настоящем времени | нельзя; вместо них обязателен блок `verb` (см. «Глаголы») |
| Прилагательные | мужской род, единственное число | нельзя | обязательна, существительное с прилагательным | обязательны `f`, `mp`, `fp` |

- **Фраза-пример** (`example`: `he`, `translit`, `ru`): простая фраза без артикля (без ה-), в которой есть слово. У существительных она подсказывает род: `זה חתול שחור` («зэ хатуль шахор», мужской), `זאת ציפור קטנה` («зот ципор катана», женский). Транскрипция фразы без знаков ударения; слово в ней записано так же, как в `translit` слова (это проверяет тест).
- **Формы прилагательного** (`forms`): `f` женский род ед.ч., `mp` мужской род мн.ч., `fp` женский род мн.ч.; у каждой формы `he`, `niqqud`, `translit`. На карточке они показываются строкой; этапы «пиши», «печатай» и викторина работают только с основной формой (`he`). Фраза-пример может использовать любую из четырёх форм.

## Глаголы

Решения владельца (14.10): полная учебная таблица форм, темы по бинъянам, озвучка всех форм (`CLAUDE.md`, «Решения по глаголам»). Реализованы формат и проверки (этап 1), карточка и озвучка форм (этап 2); режим «Практика форм» (этап 3, описание в `docs/SPEC.md`), уроки «Пааль 1–3» (этап 4) и «Пиэль 1–3» (этап 5, 15.10); формы строит генератор ниже.

В слове раздела `verbs` в `he` лежит **инфинитив** (לכתוב), а всё остальное в блоке `verb`. Этапы «слушай», «говори», «пиши», «печатай» и викторина работают только с инфинитивом, как у остальных слов.

| Поле `verb` | Обязательно | Правило |
|---|---|---|
| `binyan` | да | `paal`, `nifal`, `piel`, `hifil`, `hitpael`. Пуаль и хуфъаль (страдательные, у них нет инфинитива) добавим отдельным уроком |
| `root` | да | 3–4 буквы иврита без конечных форм: `כתב`. Только сильные корни: слабые (гзары) теряют или меняют буквы корня, для них понадобятся поле `gizra` и своя проверка |
| `present` | да | причастие, 4 формы: `ms fs mp fp` (м.р. ед., ж.р. ед., м.р. мн., ж.р. мн.) |
| `past` | да | 9 форм: `1s 2ms 2fs 3ms 3fs 1p 2mp 2fp 3p` (у 1-го лица и у 3-го лица мн.ч. род не различается) |
| `future` | да | 10 форм: `1s 2ms 2fs 3ms 3fs 1p 2mp 2fp 3mp 3fp` |
| `imperative` | нет | 4 формы: `ms fs mp fp`. Если у глагола повелительного наклонения нет, блок удаляют целиком; неполный блок нельзя |

Ключ формы читается так: цифра это лицо (1, 2, 3), `s` единственное и `p` множественное число, `m` и `f` род. Полная таблица: до **27 форм** на глагол (4 + 9 + 10 + 4). Каждая форма это `{ he, niqqud, translit, audio? }`, как у форм прилагательных: `he` без огласовок, `niqqud` для озвучки, транскрипция по стандарту ниже. У форм с одинаковым написанием должны быть разные огласовки и транскрипция там, где они различаются (в прошедшем «ты м.» ката́вта и «ты ж.» ката́вт обе пишутся כתבת), совпадающие формы (в будущем «ты м.» и «она» תכתוב) остаются одинаковыми.

Из подписей и местоимений для экрана в `packages/shared/src/verbs.ts`: `VERB_FORM_LABELS` («я», «ты (м.)», «она»), `VERB_PRONOUNS_HE` (אני, אתה, את…), названия времён `VERB_TENSE_TITLES`, названия бинъянов `BINYANIM`.

Пример структуры (образец «писать», полностью в `content/verbFixture.ts`):

```json
{
  "he": "לכתוב", "niqqud": "לִכְתּוֹב", "translit": "лихто́в", "ru": "писать",
  "example": { "he": "אני כותב מכתב", "translit": "ани котев михтав", "ru": "Я пишу письмо" },
  "verb": {
    "binyan": "paal",
    "root": "כתב",
    "present": { "ms": { "he": "כותב", "niqqud": "כּוֹתֵב", "translit": "коте́в" }, "fs": {}, "mp": {}, "fp": {} },
    "past": { "1s": {}, "2ms": {}, "2fs": {}, "3ms": {}, "3fs": {}, "1p": {}, "2mp": {}, "2fp": {}, "3p": {} },
    "future": { "1s": {}, "2ms": {}, "2fs": {}, "3ms": {}, "3fs": {}, "1p": {}, "2mp": {}, "2fp": {}, "3mp": {}, "3fp": {} },
    "imperative": { "ms": {}, "fs": {}, "mp": {}, "fp": {} }
  },
  "reviewed": false
}
```

(в примере у остальных форм поля опущены для краткости; в файле урока у каждой формы все три поля.)

### Темы по бинъянам

Темы глаголов устроены по бинъянам: `topicId` равен ключу бинъяна (`paal`, `piel`, `hifil`, `nifal`, `hitpael`), в теме только глаголы этого бинъяна (проверяет тест), поэтому повторение само показывает схему образования форм. Названия тем на экране: «Пааль», «Пиэль», «Хифъиль», «Нифъаль», «Хитпаэль». Первые 3 урока темы бесплатные, как везде. Тематические темы со смешанными бинъянами («Движение», «Речь») появятся позже, у них `topicId` не совпадает с бинъяном, бинъян виден на карточке.

### Правила проверки глагола (`verbProblems` в `content/rules.ts`)

- Бинъян из списка, корень 3–4 буквы без конечных форм.
- Все формы на месте и нет лишних ключей; повелительное наклонение целиком или совсем нет.
- В инфинитиве и в **каждой** форме есть буквы корня в том же порядке (ловит опечатки и пропущенные буквы).
- Каждая форма: огласовки того же слова (`niqqud` совпадает с `he`), ударение и согласные транскрипции по тем же правилам, что у слов (односложная форма без знака ударения: «ктов», а не «кто́в»).
- Бинъян соответствует написанию: инфинитив нифъаль, хифъиль, хитпаэль начинается с לה, остальных с ל; причастие м.р. ед.ч. нифъаль начинается с נ, пиэль, хифъиль, хитпаэль с מ.
- Фраза-пример содержит глагол в настоящем времени.
- Блок `verb` есть у каждого глагола и только у глаголов; в теме-бинъяне все глаголы этого бинъяна.

Тест не заменяет проверку носителем: он не знает, правильно ли выбраны гласные и ударение, и не сверяет форму с настоящей таблицей спряжения.

### Генератор форм (сильные корни пааль и пиэль)

Для сильных корней формы строит генератор `content/verbGen.ts`: `conjugatePaal(корень)` и `conjugatePiel(корень)`. Общее для обоих: иврит, огласовки с дагешем по правилам бегадкефат (в начале слова и после немой шва, но не после гласной и подвижной шва), конечные формы, ךְ со знаком шва, транскрипция с ударением (в прошедшем окончания -ти, -та, -ну безударные: ката́вти, ката́вта, ката́вну, а -тем, -тен и 3-е лицо ударные; ударение на предпоследнем слоге у ж.р. настоящего и у форм на -на). Ударение в 1s, 2ms, 1p прошедшего исправлено 15.10 (раньше было на окончании: «катавти́»), озвучка от этого не менялась.

**Пааль.** Только сильные корни с холамом в будущем: без гортанных א ה ח ע, без י ו в корне, без נ в начале, без одинаковых букв, без корней с «син» (שׂ: שרף, שכר, שלט, שפט…) и без глаголов с патахом в будущем (ללמוד, ילמד). Образец «писать» (`KATAV` в `content/verbFixture.ts`) совпадает с результатом генератора форма в форму.

**Пиэль (15.10).** Вторая буква корня удвоена во всех формах (дагеш хазак: מְדַבֵּר, ב с дагешем читается «б», כ «к», פ «п»). Приставки לְ מְ תְּ יְ נְ с подвижной шва, она читается «е» (ледабе́р, медабе́р, едабе́р), у 1-го лица будущего אֲ «а» (адабе́р); первая буква корня после такой приставки без дагеша (леваке́р). В начале слова (прошедшее и повелительное) дагеш у ב ג ד כ פ ת: бике́р, пате́р. Прошедшее пишется полным письмом с י после хирика: דיבר, דיברתי (огласовки דִּיבֵּר). Ограничения те же, что у пааль, и ещё два: вторая буква не ר (она не удваивается, гласная перед ней меняется: בֵּרֵךְ) и третья не נ и не ת (сливаются с окончаниями: סִמַּנּוּ). Образец «говорить» (`DIBER` в `content/verbFixture.ts`) набран вручную и совпадает с результатом генератора форма в форму.

Каждый генератор отклоняет неподходящий корень (`paalRootProblems`, `pielRootProblems`). Для остального (гортанные, слабые корни, хифъиль и другие бинъяны) нужны свои схемы. Тесты: `content/verbGen.test.ts`.

Состав уроков (корень, перевод, фраза-пример) лежит в `content/verbLessons.ts` (`PAAL_LESSONS`, `PIEL_LESSONS`, темы в `VERB_TOPICS`). Файлы создаёт `npm run content:verbs`: без параметров все недостающие уроки обеих тем, `--binyan piel` только одна тема, `--binyan piel --lesson 2` один урок (`--lesson` без `--binyan` относится к пааль), `--dry-run` только проверка. Существующий файл урока команда не перезаписывает.

Что генератор гарантирует: полноту таблицы, корень во всех формах, согласованность огласовок, дагеша и транскрипции, ударение. Что он **не** гарантирует: что форма так говорится по-настоящему. Поэтому уроки создаются с `reviewed: false`, носитель проверяет таблицы, а исправления вносят прямо в JSON. После правки носителем генератор для этого урока больше не запускают.

### Озвучка форм

Озвучиваются все формы: файлы `/audio/<id слова>-form-<время>-<ключ>.mp3` (например `paal-1-write-form-past-3ms.mp3`), до 27 файлов на глагол, около 270 на урок. Скрипт озвучки (`tools/generate-audio.mjs`, список заданий в `tools/audio-jobs.mjs`) создаёт эти файлы действием `publish` и пишет `audio` в форму; текст в синтезатор уходит с огласовками (`niqqud`). Точечно: `--only <id слова> --force`, `--kinds form`. Тест `content/audioJobs.test.ts` проверяет, что имена файлов совпадают с `verbFormAudioPath` и что `audio` попадает в нужную форму, другой тест проверяет, что заполненный путь называется по правилу и файл существует.

### Новый урок глаголов

```
npm run content:new -- --topic-id paal --number 1 --section verbs --topic "Пааль" --title "Первые глаголы" \
  --keys write,read,learn,guard,ask,send,close,open,hear,wear
```

Команда создаёт все 27 форм пустыми; в теме-бинъяне бинъян подставляется сам. Автору остаётся вписать корень, инфинитив, все формы, фразу и перевод. Если повелительного наклонения у глагола нет, блок `imperative` удаляют целиком. Для проверки носителем `npm run content:report -- --list` печатает формы по временам одной строкой на время.

## Уроки алфавита

Алфавит это шесть уроков (`alphabet-1` … `alphabet-6`) в теме `alphabet` и разделе `alphabet`. Единица изучения здесь буква: 27 форм (22 буквы и 5 конечных ך ם ן ף ץ), каждая своей карточкой. Решения владельца (13.10): алфавитный порядок, конечная форма сразу после обычной и в том же уроке, весь алфавит бесплатный, этапы «слушай», «пиши», «печатай» (без «говори»), викторина 20 вопросов.

| Урок | Буквы |
|---|---|
| `alphabet-1` | א ב ג ד ה (5) |
| `alphabet-2` | ו ז ח ט י (5) |
| `alphabet-3` | כ ך ל מ ם (5) |
| `alphabet-4` | נ ן ס ע פ ף (6) |
| `alphabet-5` | צ ץ ק ר ש ת (6) |
| `alphabet-6` | ג׳ ז׳ צ׳ (3): звуки дж, ж, ч, которых нет в иврите |

Состав уроков задан константой `ALPHABET_GROUPS` в `packages/shared/src/constants.ts`; файл урока должен содержать ровно свою группу в этом порядке.

| Поле урока | Правило |
|---|---|
| `id` | `alphabet-<номер>`, совпадает с именем файла |
| `topicId`, `section` | всегда `alphabet` |
| `topic` | «Алфавит», одинаково во всех уроках |
| `number` | подряд с 1, не больше 6 |
| `free` | всегда `true` |
| `title` | название урока |
| `letters` | 5–6 букв своей группы, в `alphabet-6` три формы с гереш |

### Формат буквы

| Поле | Обязательно | Правило |
|---|---|---|
| `id` | да | `<id урока>-<ключ буквы>`, ключи в `LETTER_KEYS` (`alphabet-1-alef`, `alphabet-3-kaf-final`); уникален во всём наборе, в том числе среди слов и уроков. **Не меняем никогда**: прогресс привязан к нему |
| `he` | да | сама форма: один символ, а у звуков дж, ж, ч буква и знак гереш `׳` (U+05F3): `ג׳`, `ז׳`, `צ׳` |
| `name.he` | да | название буквами без огласовок (אלף, «כף סופית» у конечной формы) |
| `name.niqqud` | да | то же название с огласовками, уходит в синтезатор |
| `name.ru` | да | русское название ровно как в `LETTER_NAMES` (его же показывает запись шаблонов): «алеф», «конечная каф»; у формы с гереш «<название> с апострофом» («гимель с апострофом»), см. `letterRuName` |
| `sound` | да | звук кириллицей, как видит ученик («д», «б (с точкой внутри) или в (без точки)»); у молчащих букв объяснение |
| `example` | да | слово-пример: `he`, `niqqud`, `translit`, `ru`, необязательные `image` и `audio` |
| `audio` | нет | озвучка названия: `/audio/<id буквы>.mp3`, заполняет скрипт озвучки |
| `reviewed` | да | как у слов: `false` до проверки носителем |

Правила слова-примера (`content/rules.ts`, `ALPHABET_RULES`):

- у обычной буквы слово начинается с неё, у конечной формы заканчивается ею, у формы с гереш начинается с буквы и знака (ג׳ינס; гереш обязателен, без него слово другое);
- конечные буквы стоят только в конце слова, а в конце слова нет обычных форм вместо конечных;
- огласовки того же слова, транскрипция по стандарту ниже (ровно один знак ударения, согласные на месте);
- буквы и слова-примеры не повторяются внутри алфавита; слово-пример может быть и словом обычного урока (тогда `image` и `audio` те же файлы).

Примеры берём только из слов, которые владелец может показать носителю языка на проверку; всё, что подготовил автор, остаётся `reviewed: false`.

### Урок со звуками дж, ж, ч (`alphabet-6`)

В иврите нет звуков «дж», «ж», «ч» (решение владельца, 14.10). В заимствованных словах их пишут обычной буквой со знаком **гереш** (апострофом `׳`, U+05F3): ג׳ дж (ג׳ינס «джинсы»), ז׳ ж (ז׳קט «пиджак»), צ׳ ч (צ׳יפס «картошка фри»). Это не новые буквы, а три формы, поэтому урок устроен иначе:

- этапы «слушай» и «печатай» (без «пиши»: у этих форм нет шаблонов рукописного ввода, рисунков владельца они не требуют); на клавиатуре в этом уроке есть клавиша `׳`, форму набирают двумя нажатиями (буква, затем гереш);
- викторина 9 вопросов: «послушай название и выбери букву», «посмотри на букву и выбери название», «найди на клавиатуре», по 3 вопроса каждого типа, в выборе три варианта; сдан при 7 из 9 (80% вниз), третья ошибка прерывает (`GERESH_QUIZ_RULES`);
- ключи в `LETTER_KEYS` (`gimel-geresh`, `zayin-geresh`, `tsadi-geresh`), названия «гимель с апострофом» и т. д. (на иврите «גימל עם גרש»), `he` и `niqqud` слова-примера допускают гереш (схема: `hebrewGeresh`, `niqqudGeresh`);
- в транскрипции односложные слова без знака ударения (джинс, чипс), как у всех слов;
- озвучка отправляет гереш в синтезатор обычным апострофом (`tools/generate-audio.mjs`); на слух проверить, что слышно именно дж, ж, ч.

### Файлы и озвучка букв

- Картинка слова-примера: `/words/<id буквы>-example.svg` (или png, webp), либо файл слова из обычного урока.
- У буквы две озвучки: название (`audio`, `/audio/<id>.mp3`) и слово-пример (`example.audio`, `/audio/<id>-example.mp3`). Отдельного файла «звука» нет.
- Новая заготовка урока: `npm run content:new -- --topic-id alphabet --number N --title "..."` (номер должен быть следующим по порядку).

## Стандарт транскрипции (кириллицей)

Рабочий стандарт: сложился в «Животные 1», сверен с ними. Носитель языка и владелец его утверждают вместе с первой проверкой слов.

**Допустимые символы** (проверяет схема): строчные `а б в г д е ж з и й к л м н о п р с т у ф х ц ч ш ь э ю я`, пробел и дефис между частями, знак ударения U+0301. Нельзя: `ё ы ъ щ`, заглавные, латиница, цифры, знаки препинания.

**Согласные:**

|---|---|---|
| ב | `в`; с дагешем (בּ) `б` | בּ: «ахба́р»; ב без дагеша: «ке́лев» |
| ג / ג׳ | `г` / `дж` | |
| ד | `д` | |

| ח | `х` | «хату́ль» |
| ט, ת | `т` | |
| כ ך | без дагеша `х`; с дагешем (כּ) `к` | «ке́лев» (כּ), «ахба́р» (כ без дагеша) |
| ל | `л` | |
| מ ם | `м` | |
| נ ן | `н` | |
| ס | `с` | |

| ק | `к` | |

| ה | в конце слова не пишем (только с мапиком: `х`), в начале и середине `х` | «пара́» |
| ו | согласная `в`, гласная `у` или `о` | |

**Удвоение** (дагеш хазак) не передаём: пишем одну букву.

**Гласные:** `а`, `е`, `и`, `о`, `у`. Букву `э` пишем в начале слова, после гласной и в служебных словах «зэ» (זה); после согласной обычно `е`.

**Ударение.** В слове из двух и более слогов ставим ровно один знак ударения (комбинирующий U+0301) сразу после ударной гласной: `хату́ль`, `ке́лев`, `арье́`. В слове из одного слога знака нет (`сус`, `даг`, `пиль`). Слог = гласная буква. Слова через пробел или дефис проверяются по частям. В транскрипции фраз-примеров ударение не ставим. Большинство слов иврита ударные на последнем слоге; частые исключения: существительные типа «келев», «сефер» (ударение на предпоследнем).

**Что проверяют тесты:** допустимые символы (схема), знак ударения по числу слогов (`stressProblems`) и что согласные иврита есть в транскрипции в том же порядке (`skeletonProblems`: ловит опечатки вроде «сипор» вместо «ципор», но не заменяет проверку носителем).

## Проверка носителем (`reviewed`)

- Иврит, огласовки, транскрипцию, ударения, фразы и переводы готовит автор, но настоящей проверкой считается только проверка носителем языка.
- Новые слова и буквы всегда `reviewed: false`. Тест не запрещает их публиковать (приложение показывает всё), но `npm run content:report` считает и перечисляет непроверенные, а `-- --list` печатает их в виде для носителя.
- Носитель присылает замечания, автор исправляет, затем `reviewed` заменяется на `{ "by": "Имя", "at": "ГГГГ-ММ-ДД" }`. Если слово исправлено после проверки, `reviewed` возвращается в `false`.
- Если слово исправлено, меняется и озвучка: удалить файл `apps/web/public/audio/<id>.mp3` и запустить workflow заново (без `force` существующие файлы не трогаются).

## Как добавить урок

1. `npm run content:new -- --topic-id <ключ темы> --number <номер> --title "<название>" --keys <10 латинских ключей через запятую>`. Для новой темы добавить `--section` и `--topic`. Команда создаёт заготовку (поля по разделу, id слов, `free` по номеру) и обновляет реестр.
2. Заполнить пустые поля слов. Пока они пусты, `npm run validate:content` краснеет: так задумано.
3. Если есть картинка, положить файл в `apps/web/public/words/<id слова>.svg` и указать `image`.
4. `npm run validate:content` и `npm run content:report`: без нарушений.
5. Закоммитить и запушить в `main`.
6. Озвучка: GitHub → Actions → «Озвучка слов» → action `publish`, голос `he-IL-Wavenet-A`, текст `niqqud`, без `force` (`docs/AUDIO.md`). Workflow сам запишет файлы и поле `audio`.
7. Передать список `npm run content:report -- --list` носителю языка, после проверки проставить `reviewed`.

Если файл урока удалён или переименован, выполнить `npm run content:index`: тест реестра сообщит, если это забыть.

## Что проверяют автоматические проверки

`npm run validate:content` (то же в `npm test`, `npm run check`, GitHub CI и в сборке Cloudflare):

- **Схема** (`schema.test.ts`): поля и типы, 10 слов, `free` по номеру, обязательные поля по разделам, формат `reviewed`, `id`, путей к картинке и озвучке; число слов и граница бесплатных уроков в схеме совпадают с константами `shared`; имя файла равно `id`.
- **Слова** (`content.test.ts`): `he` без огласовок и конечные формы на месте, `niqqud` с огласовками для той же основы, транскрипция (ударение и согласные), уникальность `he` и `ru` внутри урока, фраза содержит слово (иврит и транскрипция), фраза без артикля, формы прилагательного, существование файлов `image` и `audio`.
- **Набор** (`topics.test.ts`, `rules.ts`): `id` урока, уникальность id, одинаковые название и раздел темы, номера подряд с 1, бесплатные ровно первые 3, нет повторов иврита внутри темы.
- **Глаголы** (`verbs.test.ts`, `rules.ts`, `content.test.ts`): блок `verb` по схеме (бинъян, корень, 4 + 9 + 10 форм и необязательные 4 повелительного), `verbProblems` на образце и на плохих данных, правила набора (блок `verb` только у глаголов, тема-бинъян, фраза с настоящим временем, названия файлов озвучки форм).
- **Алфавит** (`alphabet.test.ts`, `rules.ts`): схема урока алфавита, состав букв по `ALPHABET_GROUPS`, id по ключам, названия как в `LETTER_NAMES`, правила слова-примера, существование файлов `image` и `audio`, уникальность id среди уроков, слов и букв (`crossProblems`); сами правила проверены на плохих данных.
- **Реестр** (`registry.test.ts`): `content/registry.ts` совпадает с файлами в `content/lessons`.
- **Инструменты** (`template.test.ts`, `rules.test.ts`): шаблон нового урока и сами правила проверены на плохих данных.

Картинка и озвучка необязательны: их отсутствие не ломает проверку, а видно в `content:report`.
