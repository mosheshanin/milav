# Контент: формат урока, правила и как добавить урок

Контент живёт в `content/` как данные (JSON), а не в коде. Продуктовые решения: `docs/SPEC.md` (разделы «Контент», «Слово», «Урок»), решения владельца: `CLAUDE.md`. Здесь техническое описание формата и порядок работы.

## Иерархия и правила

- Раздел → тема → урок → слова. Разделы: Существительные (`nouns`), Глаголы (`verbs`), Прилагательные (`adjectives`).
- В уроке ровно 10 слов (`WORDS_PER_LESSON`).
- В каждой теме первые 3 урока бесплатные, остальные платные (`FREE_LESSONS_PER_TOPIC`), независимо от числа уроков.
- Тема не хранится отдельным файлом: она задаётся полями `topicId` (постоянный латинский ключ) и `topic` (название на экране) в каждом уроке. Порядок тем на главной сейчас определяется ключом темы и номером урока (`content/registry.ts`); явный порядок и манифест появятся вместе с платными уроками (ROADMAP п. 5).
- **id слов не меняем никогда**: прогресс пользователей привязан к ним, сервер находит слово по id (`findWord`).

## Файлы и команды

| Что | Где |
|---|---|
| Урок | `content/lessons/<id урока>.json` (один урок: один файл, имя файла равно `id`) |
| Схема формата | `content/schema.json` (в уроке `"$schema": "../schema.json"`: редактор подсказывает поля) |
| Правила, которых нет в схеме | `content/rules.ts` (транскрипция, правила набора) |
| Реестр уроков в приложении | `content/registry.ts` (создаётся командой, руками не правится) |
| Картинки слов | `apps/web/public/words/` |
| Озвучка | `apps/web/public/audio/` (создаёт workflow, `docs/AUDIO.md`) |

```
npm run content:new -- --topic-id animals --number 2 --title "Дикие животные" --keys wolf,fox,bear,deer,monkey,camel,giraffe,zebra,tiger,crocodile
npm run content:index          # обновить реестр после добавления или удаления файла урока
npm run validate:content       # все проверки контента (входит в npm test и npm run check)
npm run content:report         # сводка: темы, непроверенные слова, слова без картинки и озвучки
npm run content:report -- --list   # слова для носителя языка: огласовки, транскрипция, фразы
```

## Формат урока

| Поле | Тип | Правило |
|---|---|---|
| `id` | строка | `<topicId>-<номер>`, например `animals-1`; совпадает с именем файла |
| `topicId` | строка | постоянный ключ темы, латиница в нижнем регистре, например `animals` |
| `section` | `nouns` / `verbs` / `adjectives` | раздел |
| `topic` | строка | название темы на экране, одинаковое во всех уроках темы |
| `number` | целое | номер урока в теме, подряд с 1 |
| `free` | boolean | `true` у уроков 1–3, у остальных `false` |
| `title` | строка | название урока |
| `words` | массив | ровно 10 слов |

## Формат слова

Общие поля:

| Поле | Обязательно | Правило |
|---|---|---|
| `id` | да | `<id урока>-<ключ слова>`, например `animals-1-cat`; уникален во всём наборе |
| `he` | да | иврит только буквами, без огласовок; конечные формы (ך ם ן ף ץ) только в конце слова |
| `niqqud` | да | то же слово с огласовками; без огласовок совпадает с `he`. Уходит в синтезатор, на экране не показывается |
| `translit` | да | транскрипция кириллицей по стандарту ниже |
| `ru` | да | перевод на русский |
| `reviewed` | да | `false`, пока не проверил носитель языка; после проверки `{ "by": "Имя", "at": "2026-10-13" }` |
| `image` | нет | `/words/<id слова>.svg` (или png, webp); без картинки карточка показывает запасной вариант |
| `audio` | нет | `/audio/<id слова>.mp3`, заполняет скрипт озвучки |

Поля по разделам:

| Раздел | Основная форма в `he` | `gender` | `example` | `forms` |
|---|---|---|---|---|
| Существительные | единственное число | обязателен: `m` или `f` | обязательна | нельзя |
| Глаголы | инфинитив (לאכול, «есть») | нельзя | обязательна, фраза с глаголом в настоящем времени | нельзя |
| Прилагательные | мужской род, единственное число | нельзя | обязательна, существительное с прилагательным | обязательны `f`, `mp`, `fp` |

- **Фраза-пример** (`example`: `he`, `translit`, `ru`): простая фраза без артикля (без ה-), в которой есть слово. У существительных она подсказывает род: `זה חתול שחור` («зэ хатуль шахор», мужской), `זאת ציפור קטנה` («зот ципор катана», женский). Транскрипция фразы без знаков ударения; слово в ней записано так же, как в `translit` слова (это проверяет тест).
- **Формы прилагательного** (`forms`): `f` женский род ед.ч., `mp` мужской род мн.ч., `fp` женский род мн.ч.; у каждой формы `he`, `niqqud`, `translit`. На карточке они показываются строкой; этапы «пиши», «печатай» и викторина работают только с основной формой (`he`). Фраза-пример может использовать любую из четырёх форм.

## Стандарт транскрипции (кириллицей)

Рабочий стандарт: сложился в «Животные 1», сверен с ними. Носитель языка и владелец его утверждают вместе с первой проверкой слов.

**Допустимые символы** (проверяет схема): строчные `а б в г д е ж з и й к л м н о п р с т у ф х ц ч ш ь э ю я`, пробел и дефис между частями, знак ударения U+0301. Нельзя: `ё ы ъ щ`, заглавные, латиница, цифры, знаки препинания.

**Согласные:**

| Иврит | Пишем | Примечание |
|---|---|---|
| ב | `в`; с дагешем (בּ) `б` | בּ: «ахба́р»; ב без дагеша: «ке́лев» |
| ג / ג׳ | `г` / `дж` | |
| ד | `д` | |
| ז / ז׳ | `з` / `ж` | |
| ח | `х` | «хату́ль» |
| ט, ת | `т` | |
| כ ך | без дагеша `х`; с дагешем (כּ) `к` | «ке́лев» (כּ), «ахба́р» (כ без дагеша) |
| ל | `л` | |
| מ ם | `м` | |
| נ ן | `н` | |
| ס | `с` | |
| פ ף | без дагеша `ф`; с дагешем (פּ) `п` | «ципо́р» (פּ) |
| צ ץ / צ׳ | `ц` / `ч` | |
| ק | `к` | |
| ר | `р` | |
| ש / שׂ | `ш` / `с` | |
| א, ע | не пишем, пишется только гласная | «ахба́р» (ע даёт `а`) |
| ה | в конце слова не пишем (только с мапиком: `х`), в начале и середине `х` | «пара́» |
| ו | согласная `в`, гласная `у` или `о` | |
| י | согласная после согласной `ь` + гласная («арье́»), после гласной `й`; гласная `и` | |

**Удвоение** (дагеш хазак) не передаём: пишем одну букву.

**Гласные:** `а`, `е`, `и`, `о`, `у`. Букву `э` пишем в начале слова, после гласной и в служебных словах «зэ» (זה); после согласной обычно `е`.

**Ударение.** В слове из двух и более слогов ставим ровно один знак ударения (комбинирующий U+0301) сразу после ударной гласной: `хату́ль`, `ке́лев`, `арье́`. В слове из одного слога знака нет (`сус`, `даг`, `пиль`). Слог = гласная буква. Слова через пробел или дефис проверяются по частям. В транскрипции фраз-примеров ударение не ставим. Большинство слов иврита ударные на последнем слоге; частые исключения: существительные типа «келев», «сефер» (ударение на предпоследнем).

**Что проверяют тесты:** допустимые символы (схема), знак ударения по числу слогов (`stressProblems`) и что согласные иврита есть в транскрипции в том же порядке (`skeletonProblems`: ловит опечатки вроде «сипор» вместо «ципор», но не заменяет проверку носителем).

## Проверка носителем (`reviewed`)

- Иврит, огласовки, транскрипцию, ударения, фразы и переводы готовит автор, но настоящей проверкой считается только проверка носителем языка.
- Новые слова всегда `reviewed: false`. Тест не запрещает их публиковать (приложение показывает всё), но `npm run content:report` считает и перечисляет непроверенные, а `-- --list` печатает их в виде для носителя.
- Носитель присылает замечания, автор исправляет, затем `reviewed` заменяется на `{ "by": "Имя", "at": "ГГГГ-ММ-ДД" }`. Если слово исправлено после проверки, `reviewed` возвращается в `false`.
- Если слово исправлено, меняется и озвучка: удалить файл `apps/web/public/audio/<id>.mp3` и запустить workflow заново (без `force` существующие файлы не трогаются).

## Как добавить урок

1. `npm run content:new -- --topic-id <ключ темы> --number <номер> --title "<название>" --keys <10 латинских ключей через запятую>`. Для новой темы добавить `--section` и `--topic`. Команда создаёт заготовку (поля по разделу, id слов, `free` по номеру) и обновляет реестр.
2. Заполнить пустые поля слов. Пока они пусты, `npm run validate:content` краснеет: так задумано.
3. Если есть картинка, положить файл в `apps/web/public/words/<id слова>.svg` и указать `image`.
4. `npm run validate:content` и `npm run content:report`: без нарушений.
5. Закоммитить и запушить в `main`.
6. Озвучка: GitHub → Actions → «Озвучка слов» → action `publish`, голос `he-IL-Wavenet-A`, текст `niqqud`, без `force` (`docs/AUDIO.md`). Workflow сам запишет файлы и поле `audio`.
7. Передать список `npm run content:report -- --list` носителю языка, после проверки проставить `reviewed`.

Если файл урока удалён или переименован, выполнить `npm run content:index`: тест реестра сообщит, если это забыть.

## Что проверяют автоматические проверки

`npm run validate:content` (то же в `npm test`, `npm run check`, GitHub CI и в сборке Cloudflare):

- **Схема** (`schema.test.ts`): поля и типы, 10 слов, `free` по номеру, обязательные поля по разделам, формат `reviewed`, `id`, путей к картинке и озвучке; число слов и граница бесплатных уроков в схеме совпадают с константами `shared`; имя файла равно `id`.
- **Слова** (`content.test.ts`): `he` без огласовок и конечные формы на месте, `niqqud` с огласовками для той же основы, транскрипция (ударение и согласные), уникальность `he` и `ru` внутри урока, фраза содержит слово (иврит и транскрипция), фраза без артикля, формы прилагательного, существование файлов `image` и `audio`.
- **Набор** (`topics.test.ts`, `rules.ts`): `id` урока, уникальность id, одинаковые название и раздел темы, номера подряд с 1, бесплатные ровно первые 3, нет повторов иврита внутри темы.
- **Реестр** (`registry.test.ts`): `content/registry.ts` совпадает с файлами в `content/lessons`.
- **Инструменты** (`template.test.ts`, `rules.test.ts`): шаблон нового урока и сами правила проверены на плохих данных.

Картинка и озвучка необязательны: их отсутствие не ломает проверку, а видно в `content:report`.
